How should annotation sets grow over time?

Currently: ConfigureTab creates units upfront, AnnotateTab has a separate "Add Patch" button. Two mechanisms, confusing.

A

Configure Once, Extend From Annotate

ConfigureTab creates the initial set. AnnotateTab gets an "Extend Set" panel (replaces the current "Add Patch" button) that can:

  • Add more patches to the current image
  • Add new images from the dataset
  • Add more random patches across all images

All additions go through the same manifest update path. The ConfigureTab becomes read-only for active sets — you extend from where the work happens.

Pros

  • Single place to grow the set (AnnotateTab)
  • Context-aware — you're looking at the image when you decide to add more
  • ConfigureTab stays simple (initial setup only)

Cons

  • AnnotateTab gets more responsibility
  • Batch additions (e.g. "add 5 patches to every image") need UI in AnnotateTab
B

ConfigureTab Can Reopen for Active Sets

ConfigureTab shows active sets and lets you modify them — add images, change patch count, extend scope. AnnotateTab only annotates, never modifies the set structure.

  • ConfigureTab: "Edit Set" mode shows current units + lets you add more
  • AnnotateTab: pure annotation, no set management
  • Clear separation: configure = structure, annotate = content

Pros

  • Clean separation of concerns
  • ConfigureTab already has the dataset browser and patch settings
  • AnnotateTab stays focused on drawing

Cons

  • Context switch: see a problem in Annotate → go back to Configure → return to Annotate
  • ConfigureTab needs an "edit existing set" mode
C

Hybrid: Quick Add in Annotate, Batch in Configure

Split by scope of change:

  • AnnotateTab: "Add patch here" — quick, contextual, single-image additions while you're annotating
  • ConfigureTab: "Extend set" — batch operations (add images, add N patches per image, change train/val split)

Both update the same manifest. The distinction is: small targeted additions vs structural changes.

Pros

  • Best of both: quick additions stay contextual, batch stays organized
  • Natural mental model: "I need one more patch" vs "I need to restructure"
  • Closest to how people actually work

Cons

  • Two places that modify the set (but with clear scope distinction)
  • Need clear UI signals about what each tab can do
